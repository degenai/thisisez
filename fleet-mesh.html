Fleet Mesh — Kuromi hookup

Goal: EVGA machine → commands Kuromi over a private P2P mesh. Run these on Kuromi, in order. Refresh this page — it updates as we go.

Step 1 — Tailscale (the mesh)

  1. Download: tailscale.com/download/windows
  2. Install, then sign in with alex.adamczyk@gmail.com (same Google login on every fleet machine).
  3. When it's running, right-click the tray icon → Network devices, and note Kuromi's name and its 100.x.x.x address.
  4. Also install Tailscale on the EVGA machine and sign in with the same account.

Expected: both machines show each other under Network devices.

Step 2 — OpenSSH Server on Kuromi

Open PowerShell as Administrator (right-click Start → Terminal (Admin)), then paste:

Add-WindowsCapability -Online -Name OpenSSH.Server~~~~0.0.1.0
Start-Service sshd
Set-Service -Name sshd -StartupType 'Automatic'
New-NetFirewallRule -Name sshd -DisplayName 'OpenSSH Server' -Enabled True -Direction Inbound -Protocol TCP -Action Allow -LocalPort 22

Expected: each line completes quietly; the firewall rule says "created".

Step 3 — test the pipe from EVGA

On the EVGA machine, open PowerShell and type:

ssh turnipblitz@100.x.x.x

Replace 100.x.x.x with Kuromi's Tailscale address from Step 1. Enter Kuromi's Windows login password when asked. Expected: a prompt like turnipblitz@DESKTOP-H4TM788 — you're in. Type exit to leave.

Step 4 — report back

Send Alex these three facts:

  • Kuromi's Tailscale name + 100.x.x.x address
  • EVGA's Tailscale name + 100.x.x.x address
  • "SSH login works" (or the error, if any)

Then Hermes gets wired to Kuromi, and the worker kit (pfgw + sr1sieve + proth20) flies straight over the mesh. No USB. No phone relay.

Step 5 — install EVGA's key (do this on Kuromi)

Open PowerShell as Administrator on Kuromi, paste this block (it allows EVGA to log in without typing a password):

New-Item -Force -ItemType Directory "$env:USERPROFILE\.ssh" | Out-Null
Add-Content -Force "$env:USERPROFILE\.ssh\authorized_keys" "ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAIGy7ZkXYqWyncxAxpBB1qQRoUaRJykrlVsKlUrNsr/ft hermes@evga-fleet"
icacls "$env:USERPROFILE\.ssh\authorized_keys" /inheritance:r /grant "${env:USERNAME}:(R)" /grant "SYSTEM:(R)"

Expected: quiet. That's it — EVGA can now command Kuromi.

If EVGA still gets asked for a password: turnipblitz is an admin account, and Windows makes admins read keys from a system file instead. Run this block instead (same admin PowerShell):

Add-Content -Force "C:\ProgramData\ssh\administrators_authorized_keys" "ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAIGy7ZkXYqWyncxAxpBB1qQRoUaRJykrlVsKlUrNsr/ft hermes@evga-fleet"
icacls "C:\ProgramData\ssh\administrators_authorized_keys" /inheritance:r /grant "SYSTEM:(R)" /grant "Administrators:(R)"

Step 6 — the fleet dashboard (both machines run it)

On Kuromi, install Python once (PowerShell):

winget install Python.Python.3.12

Then, wherever the worker kit lives (e.g. C:\fleet), run the board:

python collect.py --hunt-dir . --port 7844 --peers "evga=http://100.95.33.76:7844"

Click Allow on the firewall prompt (private network). Then open http://localhost:7844 — the same board EVGA shows: both machines, live workers, candidates done, residues. EVGA's board auto-finds Kuromi the moment this runs.
